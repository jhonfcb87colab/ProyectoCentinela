Explicación completa: del request al DataFrame

Esta sección explica línea por línea cómo el notebook obtiene los datos desde Internet y los convierte en una tabla que PyTorch puede procesar.

1. Se construye la dirección del recurso API

endpoint_url = 'https://www.datos.gov.co/api/v3/views/8xap-gecf/query.json'

endpoint_url es una variable de texto que contiene la URL de la API Socrata. El identificador 8xap-gecf representa el conjunto de datos de producción frutícola. El notebook no descarga todavía el archivo: únicamente guarda la dirección.

2. requests.get() realiza la petición HTTP

response = requests.get(endpoint_url)
data = response.json()
Python solicita la URL
Servidor recibe GET
Servidor devuelve JSON
json() interpreta el texto
data contiene una lista

requests es una librería HTTP. Al ejecutar requests.get(), se envía una petición GET al servidor. response guarda la respuesta completa, incluyendo estado HTTP y contenido. response.json() convierte el texto JSON recibido en estructuras de Python, normalmente una lista de diccionarios.

Ejemplo conceptual: cada registro recibido puede parecerse a {"anio": "2022", "municipio": "Dagua", "produccion_toneladas": "14088.0"}. Las claves representan columnas y sus valores representan una fila.

3. Conversión de JSON a DataFrame

df = pd.DataFrame(data)

pd es el alias de pandas. Cada diccionario se interpreta como una fila y las claves comunes se convierten en nombres de columnas. El resultado es una tabla bidimensional con filas y columnas. Por ejemplo, la primera fila conocida tiene año 2022, municipio Dagua, cultivo Plátano y producción 14.088 toneladas.

4. Eliminación de columnas internas de Socrata

cols_metadata = [c for c in df.columns if c.startswith(':')]
df = df.drop(columns=cols_metadata)

Las columnas que comienzan con dos puntos son metadatos internos de la plataforma. No contienen variables agrícolas útiles para el modelo; por ello se identifican y eliminan.

5. Conversión explícita de tipos

df['produccion_toneladas'] = pd.to_numeric(..., errors='coerce')
df['anio'] = pd.to_numeric(..., errors='coerce')

pd.to_numeric() intenta convertir texto como "14088.0" a número. errors='coerce' indica que cualquier texto inválido se convierta en NaN, en lugar de detener la ejecución.

6. Eliminación de objetivos faltantes

df = df.dropna(subset=['produccion_toneladas']).reset_index(drop=True)

Se eliminan las filas cuyo valor real de producción es desconocido. No sería válido entrenar una regresión sin conocer el resultado que el modelo debe aprender. reset_index() reorganiza los índices después de las eliminaciones.

El Perceptrón Multicapa recibe los 88 valores preparados, combina cada entrada mediante capas densas y calcula una producción estimada.

ReLU y salida lineal

ReLU(x) = max(0, x) introduce relaciones no lineales y permite que la red represente patrones más complejos que una regresión lineal. La última neurona no usa ReLU ni sigmoide: para regresión se necesita directamente un número real sin comprimirlo a un intervalo.

Lectura del bloque PyTorch

nn.Linear crea pesos y sesgos entrenables; nn.ReLU transforma las activaciones negativas en cero; nn.Dropout desactiva aleatoriamente neuronas durante el entrenamiento.

class MLPFrutales(nn.Module):
    def __init__(self, input_dim, dropout_rate=0.0):
        super().__init__()
        self.network = nn.Sequential(
            nn.Linear(input_dim, 128), nn.ReLU(), nn.Dropout(dropout_rate),
            nn.Linear(128, 64), nn.ReLU(), nn.Dropout(dropout_rate),
            nn.Linear(64, 32), nn.ReLU(), nn.Dropout(dropout_rate),
            nn.Linear(32, 1)
        )

    def forward(self, x):
        return self.network(x)

Cómo se ejecuta el código de entrenamiento paso a paso

Entrenar no significa llamar una sola vez la red. Significa repetir muchas veces un ciclo que calcula errores, obtiene gradientes y modifica pesos.

1. Conversión de NumPy a tensores

train_dataset = TensorDataset(
    torch.tensor(X_train, dtype=torch.float32),
    torch.tensor(y_train, dtype=torch.float32)
)

X_train contiene las características y y_train contiene la producción conocida. PyTorch trabaja con tensores, por lo que se usa torch.tensor(..., dtype=torch.float32). TensorDataset empareja cada vector de entrada con su producción real.

2. DataLoader y lote o batch

train_loader = DataLoader(train_dataset, batch_size=32, shuffle=True)
val_loader = DataLoader(val_dataset, batch_size=32, shuffle=False)

DataLoader entrega pequeños grupos de hasta 32 registros. shuffle=True mezcla el entrenamiento antes de cada recorrido. Esto evita que el orden repetido de los datos sesgue las actualizaciones. La validación usa shuffle=False porque solo se evalúa y los resultados no dependen del orden.

3. Configuración de pérdida y optimizador

criterion = nn.MSELoss()
optimizer = optim.Adam(model.parameters(), lr=0.001)

MSELoss calcula el cuadrado de la diferencia entre predicción y producción real. Adam recorre los pesos del modelo y actualiza cada uno según su gradiente, usando una tasa inicial de aprendizaje de 0,001.

4. Ciclo interno de una época

model.train()

Activa el comportamiento propio del entrenamiento. Si hubiera Dropout, las neuronas se apagarían de manera aleatoria.

optimizer.zero_grad()

Elimina gradientes calculados previamente para que cada lote genere su propia actualización.

model(X_batch)

Realiza el forward pass: las 88 características recorren las capas ocultas hasta la salida.

loss.backward()

Aplica retropropagación y calcula cuánto contribuyó cada peso al error.

X_batch = X_batch.to(device)
y_batch = y_batch.to(device)
optimizer.zero_grad()
predictions = model(X_batch)
loss = criterion(predictions, y_batch)
loss.backward()
optimizer.step()

.to(device) mueve los datos a GPU o CPU según el dispositivo detectado por el notebook. En la ejecución registrada el dispositivo fue cuda.

5. Pérdida acumulada del entrenamiento

running_train_loss += loss.item() * X_batch.size(0)
epoch_train_loss = running_train_loss / len(train_loader.dataset)

Como el último lote puede tener menos de 32 registros, el código multiplica cada pérdida por el número real de filas de su lote. Luego divide por todas las observaciones para obtener una MSE representativa por época.

6. Validación al finalizar la época

Después de recorrer todos los lotes de entrenamiento, el código cambia a model.eval(). En esta fase:

  • el modelo deja de modificar sus pesos;
  • Dropout se desactiva y todas las neuronas se utilizan;
  • torch.no_grad() evita guardar operaciones necesarias para retropropagación;
  • se recorren los datos de validación y se calcula su MSE;
  • las listas train_losses y val_losses permiten dibujar las curvas.
Relación entre conjuntos: entrenamiento optimiza los pesos; validación permite observar generalización y comparar configuraciones; prueba permanece reservada para la medición final.

4. Cómo aprende el modelo

El cuaderno implementa un ciclo explícito de PyTorch durante 50 épocas. Una época significa que el modelo recorre una vez el conjunto completo de entrenamiento, organizado en lotes de 32 registros.

Función de pérdida

MSE promedia los cuadrados de la diferencia entre producción real y predicha.

MSE = Σ(y − ŷ)² / n

Optimizador Adam

Tasa de aprendizaje 0,001. Adam adapta el tamaño de actualización según la señal de los gradientes.

Significado de cada paso

  • zero_grad: borra gradientes acumulados del lote anterior.
  • forward: calcula la predicción pasando los datos por la red.
  • loss: mide qué tan lejos está la predicción de la producción real.
  • backward: calcula cómo contribuyó cada peso al error.
  • step: modifica los pesos para reducir la pérdida futura.

Después de cada época, el modelo entra en eval(), desactiva gradientes y calcula la pérdida de validación sin modificar los pesos.

Regularización con Dropout

Se entrenaron dos variantes: una base sin dropout y otra con dropout_rate = 0.2. Durante el entrenamiento regularizado, el 20% de neuronas de cada bloque puede apagarse aleatoriamente. Esto obliga a la red a no depender excesivamente de unas pocas conexiones.

Interpretación detallada de las métricas

MAE: da una idea directa en la unidad original. El modelo se equivoca, en promedio, unas 1.368 toneladas. Es más robusto ante valores extremos que RMSE.

RMSE: penaliza más los errores grandes porque eleva al cuadrado las diferencias antes de promediar. Al ser mayor que MAE, sugiere que existen predicciones muy erróneas o valores de producción muy heterogéneos.

R² = 0,4606: el modelo supera a una estrategia muy simple como el promedio constante, pero deja aproximadamente el 53,94% de la variabilidad sin explicar con estas variables y arquitectura.

6. Auditoría ética y riesgos

Los errores no son neutros porque pueden afectar compras, transporte, precios, empleo, apoyo público y planeación de recursos.

Subestimación

Predecir menos producción de la real puede dejar sin preparar transporte, almacenamiento o canales comerciales.

Sobreestimación

Predecir más producción puede generar anuncios optimistas, inversiones innecesarias o decisiones de compra equivocadas.

Sesgos territoriales

Municipios poco representados o categorías infrecuentes pueden recibir predicciones menos fiables si el modelo aprende peor sus patrones.

Calidad de los datos

El API puede contener errores de captura, registros incompletos o cambios de método. El modelo reproducirá defectos de los datos históricos.

Uso seguro: este modelo debe apoyar, no sustituir, el criterio técnico. Las decisiones críticas deben incorporar intervalos de incertidumbre, revisión humana y comparación con fuentes externas.

Principios de control sugeridos

  • Monitorear RMSE y MAE por municipio y cultivo.
  • Detectar si existen grupos con errores sistemáticamente mayores.
  • Conservar trazabilidad sobre la versión de datos, código y modelo.
  • Excluir decisiones individuales o discriminatorias; el análisis es agregado.
  • Actualizar el modelo con datos nuevos y validar deriva temporal.

Preguntas frecuentes de repaso

¿Por qué se usa una salida lineal?
Porque el objetivo puede tomar valores continuos. Activaciones como sigmoide comprimirían la salida y serían apropiadas para probabilidades o clasificaciones, no para toneladas sin restricciones específicas.
¿Por qué se usa MSE y no precisión?
MSE compara magnitudes numéricas y penaliza los errores grandes. Precision, recall y accuracy sirven para problemas de clasificación.
¿Dropout demostró mejorar el modelo?
En la validación final registrada, modelo base terminó con MSE 14.407.652 frente a 15.224.999 del regularizado. Por tanto, con esta ejecución y parámetros no mostró mejora. En la evaluación final sí se usó el modelo regularizado, por diseño experimental del cuaderno.
¿Qué debería mejorar la siguiente fase?
Datos climáticos, índices de vegetación, fechas más amplias y, especialmente, una evaluación temporal que prediga años futuros. También podrían añadirse transformaciones del objetivo, detección de outliers, validación por año y mejores análisis por subgrupo.
